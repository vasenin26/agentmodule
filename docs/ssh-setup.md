# Настройка SSH ключей для Docker контейнера

## Описание

При старте контейнера автоматически создается SSH ключ из переменной окружения `SSH_PRIVATE_KEY` для доступа к Git репозиториям.

### Почему нужен именно приватный ключ?

SSH аутентификация работает по принципу "публичный ключ на сервере, приватный ключ у клиента":
- **Публичный ключ** уже добавлен в настройки вашего GitHub/GitLab аккаунта
- **Приватный ключ** нужен в контейнере для подписания запросов аутентификации
- При Git операциях контейнер подписывает запросы приватным ключом, а сервер проверяет подпись публичным ключом

## Настройка

### 1. Создайте .env файл

Скопируйте `env.example` в `.env` и добавьте ваш SSH ключ:

```bash
cp env.example .env
```

### 2. Добавьте настройки в .env

Откройте `.env` файл и добавьте настройки Git пользователя и SSH ключ:

```env
# Git пользователь (обязательно для Git операций)
GIT_USER_NAME="Your Name"
GIT_USER_EMAIL="your.email@example.com"

# SSH ключ для доступа к приватным репозиториям
SSH_PRIVATE_KEY="-----BEGIN OPENSSH PRIVATE KEY-----
MIICWwIBAAKBgQDFwR8qL3N5K+JdB...
-----END OPENSSH PRIVATE KEY-----"
```

### 3. Запустите контейнер

```bash
docker-compose up --build
```

**Примечание:** Переменная `SSH_PRIVATE_KEY` автоматически передается в контейнер через `.env` файл.

## Как это работает

1. При старте контейнера запускается `docker-entrypoint.sh`
2. **Настройка Git пользователя:**
   - Проверяются переменные `GIT_USER_NAME` и `GIT_USER_EMAIL`
   - Если найдены - настраивается `git config --global user.name` и `git config --global user.email`
   - Если не найдены - выводится предупреждение
3. **Настройка SSH ключа:**
   - Проверяется переменная `SSH_PRIVATE_KEY`
   - **Если ключ найден:**
     - Создается директория `~/.ssh`
     - Записывается ключ в `~/.ssh/id_rsa`
     - Устанавливаются правильные права доступа (600)
     - Добавляются GitHub и GitLab в `known_hosts`
     - Выводится сообщение "SSH ключ успешно настроен"
   - **Если ключ НЕ найден:**
     - SSH настройка пропускается
     - Выводится предупреждение "SSH_PRIVATE_KEY не установлен - работа с приватными Git репозиториями будет недоступна"
4. После настройки Git и SSH запускается основная команда контейнера

## Что происходит без настроек

### Без Git пользователя (`GIT_USER_NAME`, `GIT_USER_EMAIL`):
- ✅ Контейнер запустится без ошибок
- ❌ Git операции (commit, push) будут падать с ошибками типа "Please tell me who you are"
- ❌ Невозможно будет делать коммиты

### Без SSH ключа (`SSH_PRIVATE_KEY`):
- ✅ Контейнер запустится без ошибок
- ✅ Публичные Git репозитории будут работать
- ❌ Приватные Git репозитории будут недоступны
- ❌ Git операции с аутентификацией будут падать с ошибками

## Безопасность

⚠️ **Важные моменты:**

- Никогда не коммитьте `.env` файл с ключами в репозиторий
- В продакшене используйте Docker secrets или менеджер секретов
- Убедитесь, что `.env` добавлен в `.gitignore`

## Проверка работы

После запуска контейнера можно проверить SSH подключение:

```bash
docker-compose exec agentmodule ssh -T git@github.com
```

Должно появиться сообщение о успешной аутентификации.
