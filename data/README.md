# AgentModule - Персистентное хранение контекста

## Описание

Папка `./data/context` используется для персистентного хранения контекста AgentModule, включая:

- Клонированные Git репозитории
- Состояние задач (TasksStorage)
- Кэш данных между перезапусками контейнера
- Временные файлы и результаты обработки

## Структура

```
data/
└── context/
    ├── repos/
    │   └── default/
    │       ├── github.com/
    │       │   └── username/
    │       │       └── repository/
    │       └── gitlab.com/
    │           └── username/
    │               └── repository/
    └── tasks_storage.json
```

## Настройка

Контекст автоматически монтируется в контейнер через Docker volume:

```yaml
volumes:
  - agent-context:/home/local/context
```

## Преимущества

1. **Персистентность**: Репозитории и состояние задач сохраняются между перезапусками
2. **Производительность**: Не нужно клонировать репозитории заново
3. **Кэширование**: Быстрый доступ к уже обработанным данным
4. **Отладка**: Возможность просмотра состояния репозиториев и задач
5. **Надежность**: Автоматическое восстановление состояния при сбоях

## Очистка

Для полной очистки контекста:

```bash
rm -rf ./data/context/*
```

## Мониторинг

Проверка размера контекста:

```bash
du -sh ./data/context
```

Просмотр содержимого:

```bash
ls -la ./data/context/repos/
```

Просмотр состояния задач:

```bash
cat ./data/context/tasks_storage.json
```

## TasksStorage

Файл `tasks_storage.json` содержит состояние задач в JSON формате:

```json
{
    "tasks": [
        {
            "id": 1,
            "title": "Task title",
            "done": false
        }
    ],
    "lastId": 1
}
```

### Особенности

- **Автоматическое сохранение**: Состояние сохраняется при каждом изменении
- **Восстановление при сбоях**: При повреждении файла создается новое состояние
- **Логирование**: Все операции логируются для отладки
- **Блокировка файлов**: Используется `LOCK_EX` для предотвращения конфликтов
